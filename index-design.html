不做什么（硬边界）
合规红线
不实现邮箱爬取、不实现代理/多账号轮换、不实现随机化间隔规避检测。不向没有同意关系的联系人发送。
技术边界
单进程单体（2C2G）：不上 Redis / 队列 / 独立 worker。SQLite + APScheduler 同进程。
送达边界
没有任何 API 能直接知道"邮件进了垃圾箱"。采用 complained + 退信 + AI 内容分析的最接近组合。

关键分支与决策点边界显性化
分支 A：Resend 渠道
域名已验证 + webhook 回传 delivered/opened/bounced/complained。发送后状态由 webhook 驱动，用户无需手动刷新。
分支 B：SMTP/IMAP 渠道
无 webhook，状态靠推送给定时扫描退信箱（DSN 解析）+ IMAP 同步。opened 状态不可见（只能到 delivered）。
分支 C：Demo / 测试模式
设置页可配"测试模式"：发送到同一账号 / 不计数 / 不走限速。渠道测试发送走此分支。

Resend vs SMTP 差异
Resend：webhook 实时回传 delivered/opened/bounced/complained，状态机完整。

边界清单

对照基准
类别边界项说明现有实现
合规 单一发件身份 一个已验证域名或已认证邮箱 渠道 is_default 唯一
合规 不实现邮箱爬取 名单只能用户导入 导入接口仅支持文件/粘贴
合规 退订名单自动排除 导入时求差集 contacts.status + import 逻辑
合规 限速不可关闭 只能调参，不能 bypass throttle 令牌桶 + 全局最小间隔
技术 单进程单体 不上 Redis/队列/独立 worker FastAPI + APScheduler 同进程
技术 SQLite 唯一存储 WAL 模式 db.py WAL + 外键
技术 前端 build 产物由 FastAPI 托管 SPA fallback main.py static + SPA fallback
送达 垃圾箱不可直接检测 complained + 退信 + AI 分析 README + DESIGN.md 明确
送达 Resend webhook 验签 svix 签名，时间戳容差 5 分钟 webhooks.py svix 验证
AI OpenAI 兼容适配 httpx 直连，非 SDK ai_adapter 薄封装
AI key 管理 .env 或界面录入存 SQLite ai_configs 表 + .env
体验 三种编辑模式切换 富文本 ⇄ Markdown ⇄ HTML TipTap + markdown-it-py
体验 快捷键 j/k 导航、c 写信、/ 搜索 前端 hooks/useShortcuts
